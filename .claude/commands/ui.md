현재 작업 중인 페이지나 컴포넌트의 UI/UX를 검토하고 개선안을 제안해줘.

## 서비스 맥락

모코지(Mocozi)는 IT계열 대학생을 위한 프로젝트·해커톤·스터디 구인 및 네트워킹 플랫폼이다.
타겟 사용자는 20대 대학생이며, 핵심 기능은 팀 구인, 기획서 시스템, 카드형 포트폴리오다.
디자인 톤은 신뢰감 있으면서도 젊고 세련된 느낌이어야 한다.

## 작업 흐름

1. `$ARGUMENTS`가 있으면 해당 파일을 읽어라. 없으면 현재 git 변경사항(`git diff HEAD`)을 보고 가장 최근에 수정한 TSX 파일을 찾아라.
2. 파일을 읽고 이 페이지가 어떤 기능을 하는 페이지인지 파악해라.
3. 아래 관점에서 순서대로 검토해라.

## 검토 관점

### 1. 기능 적합성
- 이 페이지의 핵심 목적(예: 팀 찾기, 지원서 작성, 프로필 확인)을 사용자가 즉시 인지할 수 있는가
- 가장 중요한 액션(CTA)이 시각적으로 가장 눈에 띄는가
- 불필요하거나 이 단계에서 보여줄 필요 없는 정보가 섞여 있지 않은가

### 2. UX 흐름
- 사용자가 이 페이지에서 다음에 무엇을 해야 하는지 명확한가
- 폼이나 입력이 있다면 순서와 그룹핑이 자연스러운가
- 빈 상태(empty state), 로딩 상태, 에러 상태가 고려되어 있는가

### 3. 레이아웃 / 여백
- flex/grid 구조, 정렬, 요소 간 간격이 자연스러운가
- padding/margin이 일관성 있는가
- 모바일에서 레이아웃이 깨지는 구간이 없는가

### 4. 시각적 세련도
- 폰트 크기·굵기의 위계가 명확한가 (제목·본문·보조텍스트 구분)
- 색상이 너무 많거나, 대비가 약하거나, 구식 조합은 아닌가
- 버튼·카드·인풋 등 UI 요소가 무겁거나 촌스럽지 않은가
- 2024~2025년 기준 모던 SaaS/스타트업 서비스와 비교했을 때 어색한 점이 없는가

## 출력 형식

각 관점별로 간결하게 bullet 정리. 문제가 없는 항목은 생략해도 된다.
코드 수준의 개선이 필요하면 **구체적인 Tailwind 클래스 변경안**과 함께 제시해라.
큰 리팩터링 없이 현재 구조에서 바로 적용 가능한 수준으로만 제안해라.
칭찬은 최소화하고 개선안 위주로 써라.
